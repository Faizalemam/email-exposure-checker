Privacy & removal

Reduce exposure at the source.

Removing a result from one search service does not automatically remove the original data. The safest approach is to identify the source, secure the affected account, and request deletion or suppression where appropriate.

How this frontend handles your email

The current GitHub Pages frontend validates the address locally in your browser. It does not save scans in localStorage or cookies. Until a secure backend is configured, it does not perform breach or public-profile lookups.

Do not add API keys, service credentials, private datasets, or breach data directly to the public JavaScript files in this repository.

If your email appears in a breach

  • Change the password on the affected service using a clean, trusted device.
  • Change reused passwords on any other accounts that shared the same password.
  • Enable multi-factor authentication, preferably an authenticator app or security key.
  • Review active sessions, recovery email addresses, phone numbers, and forwarding rules.

If personal details are public

  • Find the original website or profile displaying the information.
  • Use that service's privacy, account deletion, or opt-out process.
  • After source removal, request search-engine cache/result removal where applicable.
  • Keep a record of removal requests without storing unnecessary identity documents.

Verification safety

Prefer ownership verification through the affected email address. Avoid uploading passports, national IDs, or other high-value identity documents unless the recipient is verified, the request is necessary, and the transfer method is appropriately protected.

Authorized use only

This project is designed for self-checks and authorized security assessments. It should not automate password-reset, account-recovery, or other sensitive endpoints to determine whether a person has an account on a service.
